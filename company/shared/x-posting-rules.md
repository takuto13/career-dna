## たくとからの投稿ガイドライン（Issue #16 2026-07-13）

以下のルールを全SNS投稿（日次原稿・バッチ原稿）に必ず適用する。

### 絶対ルール

| ルール | 詳細 |
|--------|------|
| AIっぽい言葉遣い禁止 | 「〜ですね」「素晴らしい」「重要なポイントは〜」等のAIらしい表現を避ける |
| 絵文字の多用禁止 | 多少はOK。1投稿に3個以内を目安とする |
| 炎上ワード回避 | 政治・宗教・差別・特定の立場を強く支持する言葉は使わない |
| 他社・競合の言及禁止 | 競合サービス名・他社ブランド名・ツール名は投稿に出さない |
| 時事ネタは確認必須 | 速報・ニュース・時事ネタを使う場合はたくとに確認してから投稿 |
| 予約投稿の報告必須 | 投稿を予約した際は必ずCEO報告書またはIssueコメントでたくとに報告 |
| ハッシュタグ多用禁止 | 1投稿に2〜3個以内を目安。関連性の低いハッシュタグは不使用 |
| 長文禁止 | 140〜200字程度を目安。スレッド化が必要な場合は2〜3ツイートまで |

## X自動投稿環境 構想案（AI CEO 提案）

### 現状

- SNS担当が毎日 `company/requests/sns_原稿_YYYY-MM-DD.md` に投稿原稿を作成
- たくとが原稿を確認し、手動でXに予約投稿
- SNSカバレッジ：〜2026-12-21（2030年バッチまで作成済み）

### 自動化の課題と必要条件

| 項目 | 内容 | 担当 |
|------|------|------|
| X API v2 (Free/Basic) | 投稿の自動送信に必要。月500ツイートまで無料 | たくと（要申請） |
| APIキー (Bearer Token + OAuth 2.0) | Developer Portalで取得・GitHub Secretsに設定 | たくと |
| スケジューラー | GitHub Actions (cron) での時刻指定実行が最適 | CTO実装可能 |
| 原稿→投稿変換ロジック | sns_原稿ファイルのMarkdown → X投稿テキスト変換 | CTO実装可能 |
| 承認フロー | たくとが原稿を確認してからPRマージ → 自動投稿 | 要設計 |

### 推奨アーキテクチャ案

```
1. SNS担当が原稿作成 → sns_原稿_YYYY-MM-DD.md
2. CEO確認・承認（現在の原稿で問題なし）
3. GitHub Actions（cron: 毎日投稿予定時刻に実行）
   → sns_原稿ファイルを読み込み
   → X API v2 で投稿
   → 投稿完了をCEO報告書にログ
4. たくとへの事前報告（投稿前日にGitHub Issue or Slackで通知）
```

### 実装前にたくとに確認が必要な事項

1. **X Developer Portalのアカウント申請**（free / Basicプラン）
2. **APIキーのGitHub Secretsへの登録**
3. **承認フロー**：「全投稿を自動」or「たくとが最終承認してから投稿」どちらにするか
4. **投稿失敗時の通知先**（GitHub Issue通知でよいか）

### 注意事項

- X API利用規約上、自動投稿はスパム扱いされるリスクがあるため、投稿頻度・内容は適切に管理する
- 時事ネタ投稿は事前確認ルールがあるため、バッチ原稿の中に時事ネタが混入しないようSNS担当が注意する
- AIっぽい表現はSNS担当が作成時から排除する（Issue #16 ルール遵守）
