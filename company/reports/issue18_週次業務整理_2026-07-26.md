## 1. 毎週の定例業務（箇条書き）

週3稼働：**月・水・金**

### CEO（毎稼働日・このセッション）

1. GitHub Issue確認（ownerラベル含む全件）
2. handoff.md確認・前回からの引き継ぎ
3. 戦略ファイル確認（strategy.md / decisions.md / context.md）
4. BACKLOG確認（今週やるべきタスクを把握）
5. 競合調査（前回から**7日経過**した場合のみ実施）
6. CTOへの指示書作成 → `company/requests/CTO_YYYY-MM-DD.md`
7. SNS担当への指示書作成 → `company/requests/SNS_YYYY-MM-DD.md`
8. 日次報告書作成 → `company/reports/YYYY-MM-DD_CEO.md`
9. BACKLOG更新（完了済みタスクを `[x]` に）
10. handoff.md更新（次回への引き継ぎ）
11. 完了済み指示書をarchiveへ移動
12. `git commit && git push`

### CTO（指示書に従い実行）

1. SEOテキスト追加・最適化（タイプページ・jobs.html・faq.html等）
2. 構造化データ（JSON-LD）の更新・整合性確認
3. llms.txt更新（AIクローラー対応・LLMO強化）
4. sitemap.xml更新（lastmod日付）
5. robots.txt更新（LLMO対応）
6. 技術的SEO改善（デザイン変更を伴わないHTML/CSS/JS）

### SNS担当（指示書に従い実行）

1. X日次投稿原稿作成（3本/稼働日）
2. X長期バッチ原稿作成（7本/稼働日）
3. 原稿を `company/x-posts/` に保存

## 2. ファイル格納場所（シンプル版）

| ファイル種別 | 格納場所 |
|------------|---------|
| CTO指示書 | `company/requests/CTO_YYYY-MM-DD.md`（実行予定日） |
| SNS指示書 | `company/requests/SNS_YYYY-MM-DD.md`（実行予定日） |
| **X投稿原稿** | **`company/x-posts/[ファイル名].md`** ← ここに統一 |
| 日次報告書 | `company/reports/YYYY-MM-DD_CEO.md` |
| 完了済み指示書 | `company/archive/`（移動後は触らない） |
| 競合情報 | `company/shared/competitive-intel.md` |
| 引き継ぎ | `company/shared/handoff.md` |
| 戦略・方針 | `company/shared/strategy.md` |
| 意思決定ログ | `company/shared/decisions.md` |

### SNS原稿の命名規則

```
【日次投稿】  company/x-posts/sns_原稿_YYYY-MM-DD.md
【バッチ投稿】 company/x-posts/YYYY-MM-DD_SNS_バッチ_原稿.md
```

> ※ requests/ フォルダには**指示書のみ**置く。原稿ファイルは置かない。
